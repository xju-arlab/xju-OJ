# XJU-OJ 题面与数据写作规范

本 skill 是团队在 XJU-OJ 上写题、改题、造数据的统一规范。所有样板、清单、数据方案都在
`references/` 下，正文是规则与判据。

## 0. 字段与页面结构

题面在 OJ 里由这些字段组成，页面按此顺序渲染：

| 字段 | 页面位置 | 放什么 |
|---|---|---|
| `description` | 题目描述 | 背景 + 完整题意；**不放数据范围、不放样例解释、不放输入输出格式** |
| `input_description` | 输入格式 | 逐行输入说明；**数据范围用括号内嵌在对应行** |
| `output_description` | 输出格式 | 输出内容、行数、格式、答案上界 |
| `samples[].input/output` | 样例 N | 纯文本，原样保留，不加 Markdown 标记 |
| `samples[].explanation` | 样例解释 N | 为什么得到这个输出；可含公式、列表、表格 |
| `hint` | 提示 | **默认留空**；只放非范围、非样例解释的补充说明 |
| `data_range` | 独立"数据范围"栏 | **保持空**。范围一律写进输入描述，不要用这个字段 |

## 1. 四段式题面

### 1.1 描述（description）

- 背景故事可以有，但**题意必须在描述里独立成立**：输入什么、要求什么、输出什么。
- 不写输入格式细节（"第一行两个整数……"放输入描述）。
- 不写数据范围（放输入描述）。
- 不写样例解释（放样例解释字段）。
- 变量第一次出现就进数学环境：`$n$`、`$a_i$`。

### 1.2 输入格式（input_description）

- 逐行写清每行几个数、分别是什么，和描述的变量名一致。
- 数据范围用**全角括号**紧跟对应的行或变量：

  ```markdown
  第一行两个整数 $n, m$（$1 \le n \le 10^5$，$0 \le m \le n$）。
  第二行 $n$ 个整数 $a_1, a_2, \dots, a_n$（$0 \le a_i \le 10^9$）。
  ```

- **范围必须和该行变量对应**。反例（A 1042 曾出现）：`n, k, m, c, d` 在第一行，却把
  `c, d` 的范围挂到第二行的 `a_i` 后面。正确做法：

  ```markdown
  第一行输入五个整数 $n, k, m, c, d$（$1 \le k, m \le n \le 2 \times 10^6$，$0 \le c, d \le 10^9$）。
  第二行输入 $n$ 个整数 $a_1, a_2, \dots, a_n$（$0 \le a_i \le 10^9$）。
  ```

- 全局约束（所有子测试的 $n$ 之和、$T$ 组总和）写在输入描述末尾单独一句。
- **不新开"数据范围"小节**，不写 `<h5>数据范围</h5>`，不用 `data_range` 字段。
- 结构性保证（排列、连通、无重边、恰好一个环、$m=n$）可以写进括号或紧跟该行，保持原意。

### 1.3 输出格式（output_description）

- 精确到行数、每行内容、分隔符、大小写；多解/SPJ 要写清判定。
- 答案上界可以括号注明，例如：
  `一行一个整数，表示 $T_j$ 最大的 key 的编号（答案不超过 $3 \times 10^{13}$）。`

### 1.4 样例（samples）

- 每个样例单独一组 `input` / `output`，**纯文本**，不要包 ``` 或加空行。
- 题面样例 2–4 组，尽量小、能手算；大数据不要放进题面。
- **样例解释写在 `explanation` 字段**，不写进 `hint`。解释要说清"为什么是这个输出"：
  关键推导、枚举、表格都可以；公式照常用 `$...$`。
- 多行解释用段落/列表/表格，不要用 `<br>` 硬拼长文。

### 1.5 提示（hint）

- 默认留空。范围、样例解释、输入格式都不许放在这里。
- 只有确实需要补充的非范围信息（例如约定、定义、SPJ 说明）才写，且尽量短。

## 2. 数学与排版

- **所有变量进数学环境**：`$n$`、`$k$`、`$T$`、`$a_i$`、`$x_p$`、`$f(x)$`。
- 连续下标写成 `$a_1, a_2, \dots, a_n$`；禁止 `a$_1$`、`a1, a2, ..., aN`、裸 `n`。
- 分数用 `\frac{}{}`：`$\frac{n}{2}$`、`$\frac{p}{q}$`；展示公式用 `\dfrac`。不要写 `n/2`、`1/n`。
- 范围统一写法：`$1 \le n \le 10^5$`、`$n \times d \le 3 \times 10^5$`、`$10^{18}$`、
  `$|q_{i,t}| \le 10^4$`。
- 括号、逗号、冒号用中文全角；数学环境内用英文逗号分隔变量：
  `（$1 \le n, m \le 10^5$）`。
- 单位、代码名、英文专名不进数学：`TeamA`、`km/s`、`64 位`、`red`、`TeamA ScoreA ScoreB TeamB`。
- 图论题边写成 `$u, v$`，区间写成 `$[l, r]$`，模数写成 `$998244353$`。
- 图片：`![注意力示意图](/public/upload/xxx.webp){width=60%}`。
  `width` 可写百分比或像素；独立成段的图片会自动居中；小屏仍受 `max-width:100%` 限制。
- 公式必须手写在"原文"模式里。**不要从渲染页面复制公式**，也不要在"预览"里改公式：
  那样会把 KaTeX 生成的 DOM 存进题面，出现 `1≤n≤1051 \le n \le 10^51≤n≤105` 这类重复字形。
- 保存后**重新打开一次**题面核对公式；发现公式坏掉，回原文模式重写该公式，不要在原位修补。

## 3. 命名规范

- 变量固定含义：`n, m` 规模；`T` 测试组数；`N, M, K` 用于与 `n, m, k` 区分的第二组规模；
  `a, b, c` 数组或参数；`u, v` 边；`x, y` 坐标；`l, r` 区间；`p, q` 参数/模数相关。
- 下标从 1 开始；同一变量全文一致，不改名。
- 避免易混字符：`o/0`、`l/1`、`I/1`；英文名保留原拼写（`Alpha`、`Beta`、`TeamA`）。
- 题目标题：简洁中文，不加"简单/困难""XX 赛"之类前缀；专有名词保留原文。
- 样例/测试点文件：`1.in` / `1.out`、`2.in` / `2.out`……与 ZIP 导入约定一致；
  子任务目录与题包结构按 `docs/operations/problem-zip-import.md`。
- 图片 alt 写内容说明（"注意力示意图"），不要写文件名或哈希。
- 变量名、题面符号、标程/数据生成器里的变量保持同名，方便对拍和题解。

## 4. 数据造法：10+10

每题固定 **20 组数据**：10 组手造小数据 + 10 组随机/构造大数据。抽样、满分、卡常都靠这 20 组。

| 组 | 类型 | 目的 |
|---|---|---|
| 1–10 | 手造小数据 | 覆盖边界与特殊情况：最小规模、最大规模、全相同、全不同、无解/多解、特殊结构（链/星/菊花/单点）、边界坐标、$T=1$ 与 $T$ 最大 |
| 11–20 | 随机/构造大数据 | 压时限与内存：随机均匀、随机倾斜、构造最坏情况、总和上限、递归/链深度 |

- 每组在数据目录里能一眼看出用途（文件名或同目录 `notes.txt`）。
- OI 赛制写清每个测试点分值和子任务依赖；ACM 赛制给整包。
- 需要 SPJ 时附 checker 与判定说明；浮点题写清误差。
- 题面样例（2–4 组）与测试数据分开，样例要小到能手算。
- 造完用标程跑一遍全包，确认每组都在时限/内存内且答案文件非空。

## 5. 参照样板

`references/statement-templates.md` 里有 5 个可直接套的完整样板：

1. 数组/最值类（单组、两行输入）
2. 图论类（$n, m$ 边、结构保证）
3. 多测类（$T$ 组、总和限制）
4. 构造/SPJ 类（多组样例、合法性）
5. 长故事类（背景在前、题意后置、范围仍按行）

## 6. 发布前检查

逐项过 `references/checklist.md`；里面同时收录了历史踩坑（公式被 KaTeX 污染、
`a$_1$` 写法、范围错位、样例解释放 hint、独立"数据范围"小节等）。
