## 可重复验证

根 `regression.yml` 对 push 和 PR 执行前端构建、浏览器及桥接测试、隔离 PostgreSQL/Redis 后端测试、部署检查、判题协议和 CLI 回归。生产凭据不进入这些测试。

- 前端：`lint:modern`、`test:routes`、`test:auth-error`、`test:contest-submissions`、`test:contest-announcements`、`test:remote-bridge`、`test:browser`、`build`。
- 后端：隔离数据库和 Redis 下 `python manage.py test --noinput`。
- 部署：`sh -n deploy.sh`，`python -m unittest discover -s deploy/tests -p '*_test.py'`。
- 原生沙箱：在新构建的一次性 JudgeServer 镜像内运行 `server/judger/tests/Python_and_core/test.py`。测试有实际编译、资源限制和系统调用隔离，不在宿主运行 root 判题测试。
- 完整判题：一次性镜像内设置 `JUDGER_RUNTIME_TESTS=1`，运行 `server/judge-server/tests/test_runtime_integration.py`，挂载文件按该脚本说明；覆盖六种语言、SPJ、普通结果、文件 IO 与令牌拒绝。

上线验收另执行真实持续 20 分钟的独立密码测试赛。开始前、比赛中、结束后都检查权限和排名快照；不通过改时钟跳过比赛窗口，不对真实比赛批量重算。实际线上结果见 [2026-10-07 线上验收记录](acceptance-2026-10-07.md)。

## 尚存边界

- 远程平台成绩由浏览器事件提供，不能作为正式比赛唯一可信来源；独立服务端验真需要单独设计。自动化桥接测试不替代外部真实账号、验证码和平台页面实测。
- Authentik、邮件投递及第三方账号是否可用，需要外部身份或邮箱参与；只凭接口成功或模拟回调不能声称全链路已验证。
- 生产使用 Python Judger 绑定。历史 Node/Lua SDK 未适配当前沙箱，不纳入支持承诺；跨提交独立 UID 与完整读取隔离仍是后续沙箱架构事项。
- 判题消息与数据库提交尚不是持久事务发件箱。等待队列投递失败会恢复项目，重复任务不会重复计分；整机或 broker 故障期间仍需结合待判提交、队列和日志恢复，不允许清空队列“修复”。

浏览器 CI 方式参考 [Playwright 官方文档](https://playwright.dev/docs/ci-intro)；服务容器配置参考 [GitHub Actions 官方文档](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers)。
